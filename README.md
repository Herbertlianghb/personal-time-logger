# Personal Time Logger · 个人时间记录

Windows 常驻的自然语言时间记录工具。鼠标移入屏幕边缘的悬浮入口即可展开小窗，也可按 `Ctrl+Alt+T` 呼出；输入正在做的事，按 Enter 保存。支持离线队列、历史时间线、日期快选，以及本月／近一年范围的每日、每周和累计统计。

试用版本：**v1.4.7-rc.1**，桌面程序版本为 **1.4.7**。新用户从零部署到首条记录的完整流程尚未验证，当前供试用和反馈。版本内容与验证边界见 [1.4.7 试用版说明](docs/RELEASE-1.4.7.md)。项目自有代码采用 [MIT License](LICENSE)，第三方依赖继续使用各自许可证；理论来源归属不包含课程原文的再分发授权。

## 能力与依赖

桌面分发包包含 Python 和 Qt 运行时，普通用户日常无需安装开发环境。草稿、未上传原文、稳定提交 ID 和界面设置留在当前 Windows 用户目录；网络恢复且程序仍运行时会重试。真正退出后，下次打开继续补传。

服务器是原始记录与修订的保存端，桌面通过固定服务器公钥的 SSH 设备凭证访问。**当前没有独立离线账本模式或公共托管服务器**：首次绑定仍需要用户自己的服务器。离线队列用于已配置客户端的暂存，不能代替服务端。

飞书自建应用负责本人单聊接收、保存回执和可选的桌面聊天镜像；正式 Base 写入需要额外配置自己的 Base、字段和应用权限。模型解释是独立可选阶段，当前实现仅适配本机 Codex CLI；Claude 可以协助安装和配置，但不是当前批处理解释器。模型或电脑不可用时，服务端仍可保存原文。Notion 没有内置 OAuth 或自动安装流程，`notion_sync` 只是外部复盘流程的门禁；本项目不会替陌生用户创建自动化。

界面分别显示本机保存、服务器保存、聊天镜像、模型整理和正式飞书核验。某一阶段成功不代表后续阶段完成。正式写入默认关闭，首次使用可以只启用原文保存。

## 日常使用

- Enter 记录，Ctrl+Enter 换行。中文输入法选字期间不会发送。
- 点击或用键盘进入输入框时，示例小字立即隐藏，拼音组字期间也不显示；只在输入框为空、未组字且失去焦点时重新显示。
- Windows 默认显示深绿色悬浮入口，可拖动并吸附到所在屏幕的左侧或右侧，位置会保存。鼠标停留约 250 毫秒展开原有记录小窗；悬停不主动取得输入焦点。点击入口可切换展开／收起，点击展开时取得输入焦点；悬停展开后可点击输入框输入。手动收起后，移出入口再移入才重新触发悬停展开；拖动不算点击。
- 鼠标移开约 650 毫秒后，小窗用约 160 毫秒的动画收回悬浮入口；展开也从入口延伸。悬浮模式使用无边框小窗，不走任务栏最小化动画。
- 输入框仍有焦点或留有文字，也会在鼠标移开后保存草稿并收起，再次展开可继续输入。中文输入法正在组字、操作菜单/详情或拖动时暂缓；窗口和托盘菜单可勾选“保持展开”。
- 悬浮模式下，热力图也参与自动收起：鼠标离开热力图、记录小窗和悬浮入口后，沿用相同延迟一起收回入口；鼠标在这些窗口之间移动、使用下拉菜单或勾选“保持展开”时不收起。点击入口也可一并收起，重新打开热力图保留已选视图。
- 关闭窗口收起小窗，悬浮入口与托盘继续保留；菜单取消“悬浮入口”可恢复普通窗口方式，从托盘菜单退出才真正结束程序。MacBook 刘海适配未实现。
- 日期选择只影响历史回看，新记录仍使用实际提交时刻。
- 时间线保留未知缺口，六种显示分类为工作、生活、娱乐、学习、休息、运动；缺少项目不编造。
- 热力图按 UTC+8 自然日查看，点击日期查看明细。按已保存起止的区间计色，估算区间单独标记并与确定区间去重；排除明确 AI 执行窗口，跨午夜裁切。缺少起止时不推算热度；记录区间不等于净人工投入。
- 原文、活动经过时间、本人主动投入、AI 后台和等待分开处理。缺少起止不按聊天间隔补造分钟，重叠活动不直接重复相加。

### 活动衔接与正式记录

解释器契约 **1.2.2** 与桌面程序版本独立。上下文推断的上午/下午保留估算标记；解释器在导入前校验来源与时间，失败后最多修正一次，两次共用原有超时上限，服务端仍独立校验。归档时刷新实时分类选项；字段结构变化和正式表人工更正仍受冲突保护。

- 按明确的状态转变衔接主活动。例如“去上厕所”后报告“回来了，开始背单词”，同一条切换报告可同时作为前活动结束和新活动开始的 `report_anchor`。它表示报告锚点，不冒称精确实测时刻；没有明确切换含义的消息不用于补齐间隔。
- 暂停后明确恢复时另起一段，保留中断；单独“回来了”只确认返回，不自动恢复此前活动。计划、准备、否定和 AI 后台执行不能自动开启本人投入。
- Base 分别保存已知的活动开始和结束，未知一端留空；只有双方已知才形成活动经过窗口。`human_intervals` 单独保存有证据的连续人工投入，不因活动窗口或报告间隔而增加。经核实的报告锚点可投影到活动日期，依据保留在备注。
- 分类与项目候选依据正式 Base 实时 Schema；仅使用已有合法选项，未知归属不编造。修订时保留已有确认分类。
- 既有 PTL 记录通过有来源的新 revision 修正，保护已完成同步的不可变回执；不能重置旧任务并以同 revision 覆盖。已撤回或被替代的行保留审计，但不计为有效活动。

## 开发与构建

源码由 `time_logger/`、`config/` 和 `deploy/` 组成。服务端与桌面依赖分别锁定在 `requirements.lock.txt`、`requirements.desktop.lock.txt`。构建与安装命令见 [安装说明](docs/SETUP.md#从源码构建仅开发者)；服务器配置见 [SERVER.md](docs/SERVER.md)。构建、试运行和测试应在用户授权的隔离环境内执行，不连接维护者的部署。

项目不会在首次启动时导入维护者配置、读取维护者账号或连接维护者服务器。自己的 App Secret、设备私钥、模型登录态、数据库和截图不得放进公开源码包。
