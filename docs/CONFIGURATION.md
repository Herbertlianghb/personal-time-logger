# 配置与字段契约

所有 example 文件都是占位模板，不能直接用于真实账户。配置文件不属于源码；放在自己选择的受限目录。本机与服务端只使用自己的身份，不复制维护者部署。修改运行配置后需要按对应组件启动/重启才生效。

## 服务端 config.json

模板：`config/config.example.json`。JSON 不支持注释。秘密为 `app_secret`；其他身份标识虽然不是登录秘密，也不应附带个人业务结构公开。

| 字段 | 含义与首次值 |
| --- | --- |
| `app_id` / `app_secret` | 自己飞书自建应用的凭据，必须替换占位符 |
| `owner_open_id` | 同一应用范围内已核实的本人用户 ID，必须替换 |
| `chat_id` / `binding_verified` | 未核实单聊时 null / false；首条已允许本人单聊由服务绑定 |
| `database` / `health_file` | 自己服务端的绝对路径；独立于源码，数据库不能公开 |
| `ingest` | 原文接收开关，最小路径 true |
| `desktop_enabled` | 桌面 RPC 开关；还需要设备登记，默认模板 true |
| `desktop_chat_mirror` | 保存后同步到本人飞书聊天；默认 false，需单独启用 |
| `parse` | 解释批次与必要问题开关；首次 false |
| `accept_model_proposals` | 验证后是否接受候选；true 不等于绕过证据/revision检查 |
| `base_sync` | 正式 Base 写入开关；首次 false |
| `base_token` / `time_table_id` | 自己的 Base 和时间表，首次可 null；启用 Base/正式历史能力前必填 |
| `notion_sync` | 外部复盘门禁，首次 false；不是内置 Notion 连接器 |
| `categories` / `projects` | 自己已确认的分类和项目候选；空项目列表允许，不自动创建选项 |
| `history_interval_seconds` | 授权聊天历史补查间隔，模板3600秒；不保证平台历史绝对完整 |

程序以 UTC+8 解释自然日；系统睡前到醒来的活动周期不等于自然日，不能混算。`history_start_ms` 若不设置，首次服务初始化时刻作为补查起点；不承诺发现绑定前的全部历史。

## 桌面 device.json

首次配置界面生成，`config/device.example.json` 仅用于理解结构。字段为 `device_id`、`host`、`port`、`host_public_key`、`credential_target`。其中主机公钥格式为 `ssh-ed25519 <base64>`，不是私钥，不是服务器证书指纹字符串。`credential_target` 指向当前用户 Credential Manager 中保存的设备私钥，不能靠手改此字符串制造凭据。

现有数据或配置损坏时不自动重绑。保留 `%USERPROFILE%\.personal-time-logger`，核对本人原配置和凭据后恢复；不要把维护者路径、AppData旧副本或另一用户配置当作默认恢复源。

## 本机 worker client-config.json

模板：`config/client.example.json`。`ssh_config`、`state_file`、`offsite_directory` 都是用户自己的绝对路径；不位于公开源码包。`host` 和 `ssh_host` 使用固定别名 `personal-time-logger`；`config/ssh-config.example` 的 `HostName` 决定实际自己的服务器。

`remote_python`、`remote_cwd`、`remote_config` 与服务端安装目录一致。`codex_executable` 指向自己的可执行文件；版本与模型约束见代码。`state_file` 保存提案 outbox，不删除以“清空错误”。`offsite_directory` 供可选 `client_daemon/offsite` 使用，单独运行 `remote_worker` 不启动备份。

SSH 模板使用 `StrictHostKeyChecking yes`、独立 known_hosts 和 `BatchMode yes`，不关闭主机校验，不复制设备私钥。known_hosts 从可信服务器公钥制作；非22端口使用 `[host]:port` 格式。操作密钥应由用户在本机生成和持有，只将公钥加到自己的服务器。

## 正式 Base 字段契约

当前代码按下列固定中文名称映射，没有任意字段名的 UI 映射器。`config/field-contract.example.json` 仅描述契约，没有真实 Base/表/字段 ID。部署到自己的表前读取实时 schema；旧快照不能作为实时证据。字段名、类型或已有选项不兼容时暂停同步，不改写用户表结构。

| 字段 | 类型 | 必要性/用途 |
| --- | --- | --- |
| 时间花销 | text | 必需，活动名称 |
| 备注 | text | 必需，证据边界与幂等恢复标记 |
| 开始时间 / 结束时间 | datetime | 必需字段；单条记录值允许未知；只按允许的明确区间写入 |
| 一级分类 / 二级项目 | select | 可选，值必须已存在；未知不新增 |
| 维度 | select | 可选，已有“时间管理”选项时使用 |
| 结果记录 | text | 可选，实际结果 |
| 状态 | number | 可选，10分制状态评分，不是流程枚举 |
| AI 赋能比例 / 工作量 | number | 可选，未知保留空值，不推断 |
| 工作量单位 / 复盘 | text | 可选，原值和人工修改需保留 |

公式、关联/查找和上述允许列表外字段不写入。分类与项目来自自己的配置及实时已有选项，不能照抄作者项目。仅有活动起止报告不证明全段持续人工投入；正式字段投影使用有依据的区间，热力图的记录区间另有显示口径，不将其冒称净人工时长。

## 热力图显示口径

本月或近12个月的数据运行时从自己已配置的Base读取，服务端按范围缓存60秒；不携带作者的旧快照或演示事实。色深按可归日的已保存起止区间并集计算，UTC+8自然日裁切；确认人工投入单列，明确AI后台/AI执行窗口排除。

已保存起止且带估算说明的记录参与显示，用棕色角标或分段标记。确定区间与估算区间先取并集，重叠部分优先归为确定区间，不能重复累计。缺少起止、仅报总时长或只有睡眠估算结论时不补造区间。有记录但起止待补的日期显示斜纹，无记录的日期留白；两者都不代表已确认零投入。

六分类筛选只改变显示。空分类或其他已有分类仍可从“全部”和日期详情查看，不增加第七个筛选分类。分页查询并非原子快照，完整性始终保留partial；无法归日的旧记录不能按接收时刻强塞进某天。记录区间不能当净人工投入或项目收益。

横向统计面板提供“每日 / 每周 / 累计”。范围可选本月或截至所选月份的近12个月，累计只覆盖界面标出的范围，不声称全部历史。日均只以存在可计区间的日期为分母，其中可以包含已标记的估算；单日最多按每日并集比较。连续天数表示连续有可计区间记录，不表示实际每天都有投入或达到目标；最近连续允许当天尚无记录时截至昨日，并显示截止日期。

每周按UTC+8的周一至周日汇总，范围首尾按实际范围裁切，保留不足一周或缺失日期的提示。累计曲线只累加已有可计区间，并标明估算成分；未知日之后保持此前累计并用虚线提示，不将平段当成已确认零投入。分类之间的区间可能重叠，不能把分类数字相加作为总投入。

年范围需要服务端支持同一`heatmap`请求中的`scope="year"`；默认`scope="month"`兼容旧月度客户端。客户端按范围分别缓存，并拒绝把旧服务端的月数据当成年统计。切换每日、每周、累计或分类在已读取的范围数据上进行，不各自扫描Base。

## 配置完成标志

分阶段判断：设备身份和主机公钥固定 → 一条原文收到服务端保存回执 → 可选模型批次成功 → 可选 Base 写后回读匹配。不要仅凭配置文件存在、退出码0、健康文件或模型文字承诺声称全部接入成功。读取或运行验证的范围由当次用户授权决定。
